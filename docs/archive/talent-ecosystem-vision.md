# 人才生态愿景：角色培养、知识库与交易市场

> **文档性质**：愿景与方向文档（vision），不是实施承诺。文中所有数据模型均为草案，
> 落地前以当阶段设计评审为准。现有架构事实以代码为准。
>
> 范围：把「人的成长」从入职后扩展到完整生命周期 —— 出生/培养 → 人才市场 → 招募 →
> 入职 → 为公司创造价值 → 知识与资产的沉淀和流转。

---

## 1. 愿景总述

Eidolon 本质上是一个游戏：玩家经营一家 AI 公司。当前版本里，员工是招聘向导里
手工填出来的——没有来历、没有履历、没有过去。本愿景把角色变成游戏的核心资产：

- 角色**有来历**：或是发行方定期投放到市场的成品角色（内置知识与人生履历），
  或是玩家亲手从空白状态培养出来的作品；
- 角色**有积累**：个人知识库、技能、被证据证明的能力画像，全部可追溯；
- 角色**可流通**：唯一身份标识 + 货币系统 + 合同式交易，构成人才市场；
- 知识**分两层**：个人知识库（随人走）与公司知识库（入职后熟悉业务、
  沉淀贡献的载体）。

设计总原则继承现有架构铁律，不得因游戏化而破坏：

1. **能力只能被证据证明**——任何渠道（培养、交易、发行）都不能直接写能力分；
2. **Learned ≠ Truth**——知识可以被推翻，技能要经真实使用验证；
3. **派生不落库**（ADR-12）——Fit/Readiness 等永远请求时计算；
4. **人格只影响工作方式，不影响分数**。

## 2. 两类角色来源

### 2.1 发行方角色（官方发行）

由游戏发行方（开发者）定期投放到市场的成品角色：

- 内置完整人生履历：教育经历、项目经验、知识体系、人格特质，全部以
  证据链形式生成（见 §4），不是一组裸数值；
- 定位：市场的基础供给与价格锚点。发行节奏（每游戏周期 N 人）是发行方
  调节市场供给的阀门；
- 品质分布分层：普通 / 精良 / 稀有（履历含金量与证据置信度分布不同），
  但不标注「战力值」——玩家要自己读履历做判断，这是招募玩法的核心乐趣。

### 2.2 玩家自训角色（养成）

玩家新建一个**相对空白透明**的角色：无履历、无知识、能力未评（unrated），
但具备学习能力。之后**学什么、怎么学、学习途径是什么，由玩家自行决定**：

- 可以基于预设模板开训（见 §3），也可以完全自由养成（逐次指定学习主题、
  途径、强度）；
- 培养消耗游戏内时间与资源（货币/算力额度），是一个经营决策：
  投入越多、路径越合理，成品越好；
- 养成完成后两个去向：**留用**（直接入职自己公司）或**投放市场**（挂牌交易，
  见 §6）。自训角色是玩家的「作品」，市场交易的就是它。

两类角色进入市场后**同池竞争**：履历格式、证据结构、评估口径完全一致，
玩家读履历区分不出（也不应区分出）出身——只有内容质量的差别。

## 3. 培养模板系统

### 3.1 模板是「倾向」，不是「配方」

模板只提供概率倾向与默认学习路径，**不决定结果**。一个走完九年义务教育的人，
课外活动丰富，依然可以思维灵活、极具创新性。实现上的表达：

- 模板定义**学习阶段序列**（阶段 = 主题集合 + 途径 + 强度 + 时长）；
- 每个阶段产出服从**分布而非定值**：知识覆盖、证据强度、人格偏移都是
  带噪声的采样；
- **际遇事件**在培养过程中随机触发（竞赛获奖、遇到好老师、沉迷某个课外
  领域、项目失败……），对分布施加扰动——这是「不完全是固定的」的机制化，
  也是同一模板产出个体差异的来源。

### 3.2 三个首发模板（预设）

| 模板 | 路径 | 倾向（概率偏移，非保证） |
| --- | --- | --- |
| **学院派** | 小学 → 初中 → 高中 → 大学（12–16 年） | 基础学科知识广而扎实；考试类证据多、可靠性高 → 能力画像 confidence 高；conscientiousness 倾向偏高。短板倾向：工程实战经验少 |
| **职业派** | 九年义务教育 → 专业实训（中职/专科/培训+实训） | 专业知识聚焦、工程技能候选多、项目证据出现早 → 工程能力 score 倾向高、adaptability 倾向高。短板倾向：知识面窄、理论深度不足 |
| **自学派** | 非规范式教育（从小自学，无固定学制） | 知识分布宽而散、置信度方差大（某些领域钻得很深，某些是想当然）；curiosity / creativity / risk_tolerance 倾向高。短板倾向：能力证据少、confidence 低 → 招聘市场上的「高风险高潜力」标的 |

模板之间不设稀有度高低——三条路径产出的是**不同形状**的人才，
适配不同职位需求（Fit 引擎天然支持这种匹配），而不是强弱之分。

### 3.3 空白角色与自由养成

不用模板的角色：玩家逐次发起学习会话（主题/途径/强度自选），
系统只保证学习规则一致（见 §4 的产出规则）。自由养成的天花板更高
（可以定向堆出罕见组合），下限也更低（乱学一通就是废履历）——
这是把「培养水平」本身做成玩家技能的一部分。

## 4. 培养过程 = 入职前链路的同构复用

核心设计决策：**教育/培养不是新造一套数值系统，而是复用「学习 → 知识/技能
→ 证据 → 能力」这条入职后已存在的链路**，只是运行在一个 pre-hire 实体上。

```
学习会话（课程/实训/自学/阅读）
  → 知识条目（KnowledgeItem：topic/confidence/sources/freshness）
  → 技能候选（Skill candidate）
  → 能力证据（CompetencyEvidence：含来源与可靠性）
      ↓ 阶段评估（考试/项目/作品 —— 复用 Assessment 引擎）
  → 能力画像（score + confidence，unrated/provisional/assessed 语义不变）
```

关键规则：

1. **教育证据要「贬值」**。证据模型已有先例：`environment="mock"` 的模拟证据
   可靠性打 5 折。培养期证据按来源分级 —— 课程学习 < 考试（高可靠）<
   毕业项目/实习/竞赛（接近真实工作）。若教育证据与真实工作证据同权，
   市场上全是高分角色，招募没有区分度；区分度应来自**不同轨迹产生的
   知识结构、能力分布与置信度分布差异**。
2. **履历即证据链，可追溯、不可篡改**。每条能力分都能回链到具体学习/
   考试/项目记录（AssessmentRun.inputs_hash 机制直接复用）。发行方角色的
   「内置履历」与玩家自训履历走同一格式。
3. **人格在培养中成型**。8 维 traits 注册表现成：大量课外探索推高 curiosity，
   高强度应试推高 conscientiousness，等等——同样以概率偏移方式施加。
4. 培养期学习会话的内容生成质量（哪怕是模板库的丰富度）是**真实性预算**
   的核心投入——角色之间的差异必须是内容差异，不只是数值差异。

## 5. 两层知识库

详细现状与桥接方案见本文件 §8 的落地映射；愿景层面只固定形态：

```
个人知识库（随人走的资产）                公司知识库（组织的资产）
  KnowledgeItem scope=private              scope=department / company
  （候选人/员工持有）                        + drive/handbook 区物化的已发布知识
        │ 晋升提案 → 评审 → 物化（既有机                    ▲
        └──────────── 制的补全与接线）─────────────────────┘
```

- **个人库**：角色的私有资产，交易时随角色一起转移（是估值的一部分）；
- **公司库**：组织资产，角色离职/被交易**带不走**（公司侧已发布的知识留在公司）；
  员工在职期间的晋升链路就是「个人为公司创造知识价值」的通道；
- **检索目标架构**：混合检索（全文 + 语义向量 + scope/元数据过滤）。
  embedding 作为可插拔层：配了真实 provider 模型就启用语义检索，
  mock 模式回落 SQLite FTS5——**不作为硬依赖**。存储优先 sqlite-vec
  （保持单文件 SQLite 哲学），规模真起来再评估 Qdrant/pgvector；
- 个人库与公司库共用同一张索引，用 scope/owner 做过滤（多租户标准做法）。

## 6. 身份标识、货币与交易市场

### 6.1 唯一身份标识

每个角色（无论来源）拥有**全局唯一身份 ID**，与其证据链绑定：

- ID 在创建时签发（发行方签发官方角色；系统为玩家自训角色签发），
  终身不变、不可转让、不可伪造；
- 履历防篡改：证据与评估记录的内容哈希（复用 inputs_hash 思路），
  交易时买方可以验证「这份履历没被卖家美化过」；
- 交易、入职、晋升等全部历史挂在身份 ID 下，形成完整人生时间线
  （CareerEvent 机制向前延伸到培养期与教育期）。

### 6.2 货币系统

- **账户与流水**：每个公司一个钱包；货币变动只走复式流水账
  （ledger：每笔必有来源与去向，余额是流水的派生计数——不落库可改余额字段）；
- **货币来源闭环**：公司项目交付营收 → 工资/培养投入 → 市场买卖。
  培养是货币的出口之一，交易是货币的流通通道；
- **防刷**：培养成本（时间+货币）必须显著高于「随便养一个就卖」的回本线；
  官方发行角色的定价作为市场锚点，防止玩家间对倒刷钱（详见 §9 风险）。

### 6.3 合同式交易

最小交易单元是**转会合同**：

1. 卖方挂牌：设定底价/一口价、合同条款（首版只做一次性转会费；
   后续可扩展分成条款、回购条款）；
2. 买方报价/摘牌：货币进入**冻结（escrow）**；
3. 成交结算：冻结资金划转卖方，角色所有权变更（所属公司转移），
   身份 ID 与履历不变；
4. 流拍/撤牌：冻结解除，角色返回卖方。

个人知识库随角色转移；其在原公司期间已晋升到公司知识库的内容**不回流**，
留在原公司（卖方保有知识资产，买方买到的是人）。

### 6.4 市场形态：本地模拟先行，联网可替换

「不同玩家之间交易」在架构上是一个重大岔口。当前 Eidolon 是本地单公司
架构，联网市场意味着发行方中心化服务器、账户体系、反作弊——工程量与
运营负担都大。因此：

- **第一阶段：本地模拟市场**。发行方角色 + NPC 公司作为交易对手，
  全部撮合在本机完成；玩家体验完整的培养-挂牌-买卖循环；
- **接口抽象**：市场交易的所有读写走 `MarketAdapter` 接口
  （本地实现 / 联网实现可替换），UI 与游戏逻辑不感知差异；
- **第二阶段（可选）：联网市场**。发行方服务器做撮合与身份注册中心，
  本地仍是游戏本体；只有确认产品需要玩家间真实经济时才投入。

## 7. 新实体草案（落地前以评审为准）

| 实体 | 职责 | 关键字段（草案） |
| --- | --- | --- |
| `Character`（候选人/角色） | pre-hire 实体，培养与市场交易的载体 | identity_id（全局唯一）、origin（issued/trained）、owner_company_id（nullable=在市场）、training_template、lifecycle 状态 |
| `TrainingProgram` | 一次培养过程实例 | character_id、template_id、当前阶段、资源消耗累计 |
| `EducationEvent` | 培养期履历事件（课程完成/考试/际遇） | character_id、kind、主题、结果、证据外键 |
| `MarketListing` | 挂牌单 | character_id、卖方公司、底价/一口价、条款 JSON、状态 |
| `TradeContract` | 成交合同 | listing_id、买卖双方、金额、结算状态 |
| `Wallet` / `LedgerEntry` | 货币账户与复式流水 | 公司外键；流水：借贷双方、金额、事由、关联单据 |

入职动作 = `Character` 转为 `Employee`，知识/技能/证据/人格整包继承
（外键从 character 改写为 employee），身份 ID 不变。

## 8. 与现有架构的映射（复用清单）

| 愿景能力 | 复用的现有机制 | 缺口 |
| --- | --- | --- |
| 个人知识库 | `KnowledgeItem`（owner/scope/confidence/freshness） | 挂到 pre-hire Character；公司级浏览 UI |
| 公司知识库 | scope=department/company + 晋升提案/评审 API | 晋升物化到 drive/handbook；检索放开 scope 分层 |
| 技能养成 | Skill candidate→validated（3 次 + 80%） | Skill 缺流程本体（procedure 结构，另文讨论） |
| 能力画像 | Evidence → Assessment 引擎、inputs_hash 审计 | 教育来源的 reliability 分级 |
| 招募匹配 | Position Fit 引擎（需求 × 画像） | 对 Character 直接可用，无需改造 |
| 人格 | 8 维 traits + BehaviorPolicy | 培养期成型规则 |
| 学习过程 | LearningSession/预算/幂等 | 培养期模板驱动与际遇事件 |
| 检索注入 | retrieval.py（任务上下文） | scope 分层 + FTS5 → 可插拔 embedding |

## 9. 风险与设计注意事项

| 风险 | 对策 |
| --- | --- |
| 教育证据通胀 → 市场全员高分 | 来源 reliability 分级（§4.1）；confidence 与 score 永远并列展示 |
| 模板决定论 → 养成玩法死亡 | 分布采样 + 际遇事件扰动（§3.1）；模板只给倾向 |
| 对倒刷钱 / 市场通胀 | 官方发行定价锚；培养成本 > 最低回本线；ledger 全量审计可查 |
| 履历造假 | 证据内容哈希链；评估只认引擎输出，无人工改分入口 |
| 模拟内容空洞 → 角色差异只剩数值 | 真实性预算优先投培养期内容生成（模板库/际遇库丰富度） |
| 联网市场工程量 | §6.4 本地先行 + MarketAdapter 抽象 |

## 10. 不做清单（本愿景明确排除）

- 不做角色间的人际关系/情绪模拟；
- 不做自动晋升/自动交易（人事与交易决策永远由玩家确认）；
- 不做角色「战力总分」（score 与 confidence 分开展示是既有 UI 硬要求）；
- 不做付费货币/真实金钱交易（游戏内货币只在游戏闭环内产生与消耗）；
- 第一阶段不做联网市场、账户体系、反作弊。

## 11. 路线图（建议）

| 阶段 | 内容 | 依赖 |
| --- | --- | --- |
| K1 | 知识库桥：检索 scope 分层 + 晋升物化 drive + 公司级浏览 UI | 无（纯 SQL） |
| K2 | FTS5 全文检索 + freshness 降置信接入 | K1 |
| K3 | embedding 可插拔层（sqlite-vec + provider 绑定 + 混合检索） | 真实 provider |
| T1 | Character 实体 + 培养会话（三模板 + 际遇事件）+ 教育证据分级 | K1（共享模型） |
| T2 | 人才市场（本地模拟）：发行投放 + Fit 筛选 + 履历浏览 + 招募入职 | T1 |
| M1 | 货币系统（wallet/ledger）+ 合同交易 + escrow | T2 |
| M2 | （可选）联网市场：MarketAdapter 联网实现 + 身份注册中心 | M1 + 产品决策 |

K 线与 T/M 线共享数据模型但可并行；T/M 线依赖 K1 的检索底座
（否则「入职后熟悉公司业务」没有支撑）。
