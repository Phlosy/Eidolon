日期：2026-09-20。实施基线：`3718881`（U5）。本包实现 U6 的就绪、等待和通知语义；
M3.2 仍需 U7 的真实结构化工具往返及 U8 的管理/评审会话，不能以本包关闭整阶段。

## 同一份就绪事实

`work/readiness.readiness_report` 是 HTTP、`inspect_readiness` 内部工具及派发的共同入口。
保留 position / workspace / runtime / provider 四项，以及严格 `ready_to_work = 四项均成立`。
mock 的执行必答项仍为空；真实 Runtime 仍要求 workspace / runtime / provider，职位缺口仍为软约束。

新增字段为兼容扩展：各项带阶段、原因、执行是否必答、阻塞标志、计算时间、观察时间和有效期；
报告带执行缺口及四层说明。缺失探测返回 unknown，过期探测不能据以放行。计算过程只读数据库、
已保存的探测和目录事实，不启动 Docker、不调用模型、不自动探测 Provider。

| 层 | 事实与边界 |
| --- | --- |
| employment | 在册状态与有效主职分别解释；只认权威主职，不把兼任冒充主职 |
| provisioning | 工作区、实例和模型绑定等所需资源是否已存在；不据此证明运行健康 |
| runtime | 实例、应用、鉴权控制、能力及 Provider/选定模型的观察事实是否有效 |
| execution | 在册状态、执行必答项和当前会话占用；项目状态、任务依赖和管理暂停另由原派发内核校验 |

派发移除重复的实例/绑定简化判定，直接使用报告中的事实；保留已有原因词表、DAG 与状态机。
通知只附所需就绪解释，不复制 Runtime 策略配置。开始 WorkSession 前重新运行派发校验，
使排队后出现的离职、取消、暂停和环境失效在外部调用前被拒绝。

## 等待与持久通知

环境缺失不会改写 Task 状态、换负责人、招聘或解除管理暂停。环境恢复且原授权仍有效时可继续；
Manager 设置的 blocked 仍需明确解除。任务终态不会因负责人环境变化产生新的不可用通知。

原 `_escalated` 只在内存中保存 `(task, event)`：同一进程恢复后再次故障不再通知，重启却会重复通知。
v51 新增 `dispatch_notices` 保存观察到的周期，唯一写者为调度扫描中的 `work/dispatch_notices.reconcile`。
同一作用域/事件只允许一个未结束周期；条件消失、作用域失效或负责人变化结束旧周期，再次故障创建新周期。
周期与来源 Event 在同一事务提交，任一写入失败均回滚；没有另一张持久化就绪表。

SQLite 扫描在读取事实前使用 `BEGIN IMMEDIATE`，防止恢复或另一次扫描穿插在观察与周期落库之间。
PostgreSQL 路径使用 SERIALIZABLE 事务及相应 INSERT 方言，不发送 SQLite 锁语句；本机验收数据库为 SQLite，
没有把方言分支测试当作真实 PostgreSQL 验收。此阶段仅访问本地事实，事务提交后才广播和启动会话。

未广播周期通过部分索引查询，每批最多 100 条。失败后继续提供同一个已提交 Event ID，不再新增事件行。
`broadcast_at` 仅表示总线已接受广播安排，**不表示消费者完成**。入队后、标记前崩溃可能再次提供同一 ID；
U8/U16 必须以来源 ID 实现幂等消费和持久恢复。已结束周期不再参与补发。EventBus 普通发布在事务失败时
仍保留原有尽力广播行为，但不附带未提交的来源 ID。
