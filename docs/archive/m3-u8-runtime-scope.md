# U8：管理与评审的执行范围和回执

本批把 U7 工具桥接到已提交的非 Worker 会话用途。U8 的事件消费、后台运行器和
真实管理/评审验收仍待完成，本批不关闭 U8 或 M3.2。

## 目标与身份

每次调用从 WorkSession 的不可变出处取得 Employee、Person、公司和用途，再读取当前
人员、项目与评审请求校验。历史身份缺失、人员停用或换绑、公司变更、指定负责人变更、
项目取消或拒绝均不能沿用旧权限。缺少主职仍是软就绪项：公司内事实可以读取，写入继续
逐次经过原 Authority / Autonomy 校验。

管理会话的现有写工具限定在绑定项目内，包括通过 Task、依赖、ReviewRequest、Drive
产物间接指向的目标。评审会话只可向绑定的最新、仍开放的 ReviewRequest 提交结论。
非 Worker 的 DecisionEnvelope 也必须指向绑定项目或适用任务，避免效果与决策记录
归到不同项目。公司内其他可见事实仍可作为读取上下文；后续公司/人才动作必须另行定义
与管理目标的关系，不能借新增工具扩大当前范围。

RuntimeSession 和 TaskContext 允许空 task_id，和非 Worker WorkSession 一致；
评审任务由 ReviewRequest 解析，不伪造执行任务。模型收到用途及请求引用，工具回执保存
同一归属。旧 Worker 协议形状和没有 purpose 的旧 v1 快照保持兼容，工具目录仍只在首轮发送。

## 结论生效后的回传

PASS、REWORK、REJECT、ESCALATE 都会立即关闭评审请求。此时仅当本会话存在关联的
RuntimeOperation、DecisionRecord 和已应用 ToolAudit，且结论、备注和决定时间与实际
请求相符，才允许继续读取、重取原回执或结束确认。新增写动作均生成拒绝回执。

其他调用者已决定、未关联桥接请求的内部审计、旧请求被替代、人员失效或项目取消，均不能
开启或延续该回传阶段。正常 PASS 后项目已由既有调度流程完成时，仅在所有任务已 done
且该会话确实提交此 PASS 的情况下保留确认路径。预算、Provider、模型绑定和取消检查继续生效。

自然语言表示通过或协议 finish 都不改变 Task、Project、ReviewRequest，也不直接结束
WorkSession；后续运行器负责会话自身的收尾。

13 failed / 2 passed，再加入目标校验。最终新增 **98 项**通过，使用真实数据库、工具桥、
决策和评审服务；外部模型 I/O 为脚本替身，不能作为真实 Runtime 验收。

DAG/Handoff/黄金路径及 Worker 生命周期，共 **610 passed / 1 warning**，耗时 40.86 秒。
