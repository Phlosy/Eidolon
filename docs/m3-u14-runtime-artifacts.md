## OpenClaw 下载与来源检查

在固定 OpenClaw 2026.8.1 镜像中检查到：`artifacts.list/get` 返回产物摘要，
`artifacts.download` 才返回 base64 内容；请求参数为 `artifactId`。
原适配器读取摘要的 `content` 字段，下载失败也会返回空产物，重放则继续追加。

现在使用 U13 原 run/session 引用查询和下载，逐份核对来源与元数据，整批通过才返回。
UTF-8 原文、字节数和 SHA-256 一同携带，下载期间取消或换 run 会拒绝本次结果。
每份上限 256 KiB，整批上限 1 MiB / 32 份；URL 与二进制明确返回不支持，
不发起额外 URL 请求。通用 file 归为 `other`，不推断业务产物类型；传输错误不暴露远端正文。

测试先观察到 19 项实际失败；补充取消竞争场景又观察到 1 项失败，大小边界 3 项通过。
修复后，产物、受控协议、持久遥测、M3 契约与 Runtime 行为共 **175 项通过**。
本段 5 个 Python 文件 Ruff 与格式检查通过。第一次修复后的单测有一项错误码分类不符，
已修正并保留原日志。源码协议检查、传输替身测试均不能替代真实模型产物验收。

## Hermes 受控 workspace 清单

已增加 `eidolon.artifacts.v1` 采集协议。每次执行使用本地会话和 U13 请求键分别散列出的
目录；Worker 收到容器内输出位置、任务声明的产物类型、闭合清单格式和字节上限。
挂载位置与 Docker manager 共用常量，提示词不暴露宿主绝对路径。

采集按目录描述符逐级打开，不跟随符号链接，拒绝硬链接、FIFO 等非普通文件。
清单和全部文件通过大小、哈希、原会话/请求及读取前后状态核对后才返回；文件中途变化、
清单替换、半写或第二份文件缺失均拒绝整批。格式仍限 UTF-8，未扩展二进制交付。
Hermes 的产物能力位现在对应这个已实现的 workspace 协议。

先观察到 29 项文件边界失败；补充声明类型传递时又观察到 1 项缺字段失败。
接入回归首次有 1 项失败：旧遥测测试只模拟完成事件，没有生成文件。该测试已加强为
真实临时文件→适配器→Drive 内容核对，未放宽采集检查。最终相关 **306 项通过**，
覆盖 M2 handoff、正式评审、Drive、产物兼容与学习、Runtime 和遥测。
9 个 Python 文件的 Ruff 与格式检查通过；[workspace 验证记录](evidence/m3-u14-workspace-transport.json)。
