## 释放员工之前清理执行资源

此前，遥测写入异常或宿主取消会结束 WorkSession 并释放员工，但真实 Hermes / OpenClaw
适配器的生产协程、SSE / Gateway 等待仍可能继续运行。现在先向原 run 请求停止，并取消、
等待本地生产协程退出，然后释放执行权。收尾期间再次收到取消，也会等待清理并保留取消结果。

取消只使用已捕获的 `remote_run_id` 和 `remote_session_ref`。不再读取旧 run 缓存，
也不在引用缺失时改为停止整个共享会话。停止通信有 5 秒上限，异常正文不进入日志。
OpenClaw 的 `aborted: true` 回执不再被当作终态确认；终态查询见下文第二段。

主机完成记录移至产物采集和本地领域收尾之后。若远端已经 completed，但原产物缺失，
远端完成事实保留，主机结果记录 failed，不再提前留下无法纠正的主机成功记录。
本段不改变 Task 终态、评审要求、产物版本映射或经济计量规则，也没有数据迁移。

## 持久停止与原执行核对

v62 `62b87bef0916` 在原 RuntimeAttempt 增加 `stop_requested_at` / `stop_reason`。
首次意图先在短事务中提交，再核对原身份并发出停止；重复请求保留首次原因与时间。
旧执行的两个字段仍为 NULL，不推断旧记录是否曾被取消。原 attempt 和它引用的 WorkSession
禁止删除或通过 SQL REPLACE 替换；停止历史不允许被改写、清除或通过降级丢失。

远端终态继续使用已有 status、ended_at 和 terminal_source。`stop_state` 的含义是：

| 值 | 含义 |
| --- | --- |
| `not_recorded` | 没有保存停止意图，不能据此断言历史上从未停止 |
| `unconfirmed` | 已保存意图，尚未观察到原 run 的终态 |
| `terminal_observed` | 已观察到原 run 结束；不代表停止请求导致它结束 |

Hermes / OpenClaw 的实际 Worker 与受控轮次共用停止路径。停止和查询各最多等待 5 秒，
停止响应丢失后仍查询原 run；查询失败、运行中或身份不符都保持未确认。已有终态时不重复
发送停止。原连接、observer、run/session 和本地协程在等待前固定，调用方随后换入新句柄
也不能把查询发往新地址、把原终态写进新 attempt，或将新运行标记为已停止。

`work/runtime_stop.stop_attempt` 可从持久记录重建并停止原执行，已在新 Python 进程验证，
不重新提交任务、不读取员工当前 Runtime 偏好作为目标。原身份变更或保存意图失败时只清理
本地协程，远端保持未确认，日志不输出异常正文。没有持久 attempt 的兼容调用仍只返回
未确认停止；不能将它们作为持久恢复或真实验收证据。

已保存停止意图的会话拒绝继续准备或重用请求。首次产物验收通过服务和 SQL 两层拒绝停止后
的结果；已验收集合保持可读历史，不因后来停止而重写。后续有限技术重试需要单独限定安全
放行条件与累计预算，本段不放开这一限制，也不改变 Task 终态或正式评审要求。

本段新增 38 个停止场景、2 个迁移场景、3 个产物场景，并强化既有 Worker 清理断言。
初轮 34 失败 / 67 通过；两项存储故障测试最初在记录调用前触发断言，掩盖了旧代码的请求，

## 管理状态变化停止原 Worker

此前 PATCH、Agent 工具及状态服务把任务改为 cancelled / blocked 后，正在等待 Runtime
结果的 Worker 仍会继续运行。现在这些入口共用 Task 状态服务，在同一事务保存原运行的
停止意图，提交后通知对应 WorkSession；回滚不产生停止效果。自然完成时 Worker 会话已经
结束，不会因 Task 随后进入 in_review 被误判为管理中止。

编排器只取消自己持有的原 WorkSession 协程。即使通知丢失或关闭新派发，周期检查仍会读取
持久停止意图并完成清理。启动环境期间还没有 attempt 时，Task 状态和发送前检查阻止首次
远端调用，不伪造执行记录。进程重启后的对账仍留给 U16，不将内存通知描述为持久队列。

普通 assignee 修改继续表示下一执行者，当前会话保留原归属。旧结束回调只能释放它自己占用
的员工键；迟到的旧 WorkSession 通知不能停止当前新会话。关闭编排器先停派发，再等待其
持有的 Worker 清理完毕，直接启动的 Worker 也包含在内。Task 的取消、阻塞和正式终态均
保留原值；本段没有引入技术重试或更改失败任务语义。

既有生命周期与任务图基线 **40 项通过**后开始实施。新增 24 项场景先得到 **20 项预期失败、
4 项兼容行为通过**，覆盖实际两种适配器、PATCH、工具、状态服务、回滚、丢失通知、启动
窗口、关闭流程及旧回调。补充提交前后停止意图的可见性断言，以及无通知时发送前拦截的
2 项场景后，最终 **355 项相关检查通过**；5 个 Python 文件静态与格式检查通过。

停止意图也能被扫描发现。原身份、目标及运行绑定校验与轮次边界共用，未新增另一套权限规则。
本人提交正式 verdict 后的合法回执阶段继续运行，不会因任务 done 或请求 decided 被误停。

## 技术执行失败保留可管理任务

Worker 因 Runtime、传输、产物采集或宿主错误最终退出时，原 WorkSession 仍记录 failed，
仍在 in_progress 的 Task 进入 blocked。已有的管理状态和 failed / cancelled / done 业务
终态不被覆盖。宿主关闭而 Task 尚无其他管理结果时，同样保留为阻塞任务，等待明确处理。

会话收尾、Task 阻塞及既有 `task.blocked` 通知在同一事务保存；通知引用原 WorkSession、
错误事实和技术重试计数。该路径不再伪造 task.failed 或发出 replan_required，系统不提出
重规划方案。现有管理来源扫描能发现广播丢失的持久事件；重复收尾不再产生通知或成本。
明确业务失败的原手动路径继续保持原有行为。

Manager 经现有结构化决定与 update_task 工具解除阻塞后，才能建立下一次执行；决定及动作
保留 DecisionRecord / ToolAudit，旧会话和尝试保持原样，rework_count 不增加。这里的继续
开工测试以原远端已结束为前提；远端结果未知时的后续准入守卫和自动技术重试仍待下一段。

## 原远端执行未确认时禁止重开

原 WorkSession 已结束并不代表远端 run 已结束。现在新 Worker 同时检查同公司、同 Task
和同员工的真实执行记录；改派任务或新建会话不能绕过仍未知的原执行。管理会话检查同员工，
评审还检查同 Task，管理其他员工的失败任务仍可进行。发送新请求前再次检查其他会话，
覆盖领取到发送之间的变化。同一会话内的原请求幂等重用规则保持不变。

派发读面复用 runtime_unavailable / recipient_busy，附最多两个待核对 attempt ID。
现有调度协程向原 Runtime 查询原 run，每次最多等待 5 秒、每轮最多两个；不启动环境、
补发请求或发送停止。仍在运行、查询失败、引用缺失或原身份变化时保持未知，继续阻止新执行。
仅由已保存的真实 attempt 得出这一判断；没有 attempt 的旧会话不被补写成已知远端历史。

查到终态后，唯一遥测写入者先重新校验原连接与身份，再保存既有终态列。该观察不改写原
WorkSession 的失败、Task 状态或正式评审结果，也不接纳迟到产物。新派工仍在原领取事务
重新检查所有就绪与占用事实；管理 Runner 在核对后还重新检查预算。每员工最多持有一个
调度预检协程，关闭时会等待清理。这里的预算检查沿用已有钩子，不等于累计预算计量完成。

## 已接收 Worker 的有限等待恢复

Worker 的原请求已持久确认接收后，SSE / Gateway 等待结果期间出现传输断开、读超时或
暂时 HTTP 错误，现在可以退避后继续查询原 run。保留原请求、attempt 与 WorkSession，
不再次提交模型任务。认证、协议身份、数据库错误、已知远端失败和接收情况不明的提交
不触发自动重发；管理/评审仍要求原指定通道中的完整回复，不用终态查询代替正式响应。

每次进入或重新进入恢复前，宿主在同一短事务保存 technical_retry_count 与既有
runtime.warning。一个 WorkSession 最多获得两次许可，分别退避 0.1 / 0.5 秒，业务
rework_count 不变；并发申请共用这一上限。查询前重新检查原身份、Task 执行态和停止意图，
存储失败不能继续读取。普通运行中/未知状态轮询不冒充成功，也不算另一次模型提交。

每次查询最多 5 秒，普通轮询间隔 0.5 秒。恢复、退避和原执行共用初始截止时间，恢复不能
重置时钟；run_timeout_seconds 必须有限、为正且最多 900 秒。宿主在准备持久请求前拒绝
无效配置，避免创建从未发送却需要远端核对的 attempt。连接在等待期间变化时，终态写入
再次验证原身份，不能发布来源不明的恢复产物。

恢复成功沿用原产物收集、整批验收及正式评审流程；重试额度或时限耗尽时，沿用原 run 停止、
本地清理、WorkSession failed 和 Task blocked 收尾。退避或读取期间取消仍会清理生产协程。
已有 budget_denied 停止意图能阻止恢复读取，但本段并未提供累计费用预算的准入或计量。

新增 **36 个场景**。主实现前 **10 项预期失败、6 项拒绝路径表征通过**；初次相关回归
120 项通过。无效超时配置留下未发送 attempt 的问题另外先复现 **4 项失败、4 项表征通过**，
随后将验证移到持久请求之前。其余 12 项边界场景在实现后补充，覆盖原截止时间、每次查询
上限、停止意图、连接替换及并发计数；36 项定向检查通过。

最终 **758 项相关检查通过**，7 个 Python 文件静态与格式检查通过；原记录及源码摘要见
