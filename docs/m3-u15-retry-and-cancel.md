# U15 技术重试与远端取消

2026-09-20。U15 实施中。首段已验证本地生产协程收尾；持久停止、终态核对、有限重试、
预算与真实远端停止仍待完成。本记录不将停止请求或本地协程退出算作远端已停止。

## 释放员工之前清理执行资源

此前，遥测写入异常或宿主取消会结束 WorkSession 并释放员工，但真实 Hermes / OpenClaw
适配器的生产协程、SSE / Gateway 等待仍可能继续运行。现在先向原 run 请求停止，并取消、
等待本地生产协程退出，然后释放执行权。收尾期间再次收到取消，也会等待清理并保留取消结果。

取消只使用已捕获的 `remote_run_id` 和 `remote_session_ref`。不再读取旧 run 缓存，
也不在引用缺失时改为停止整个共享会话。停止通信有 5 秒上限，异常正文不进入日志。
OpenClaw 的 `aborted: true` 回执不再被当作终态确认；终态查询将在后续部分接入。

主机完成记录移至产物采集和本地领域收尾之后。若远端已经 completed，但原产物缺失，
远端完成事实保留，主机结果记录 failed，不再提前留下无法纠正的主机成功记录。
本段不改变 Task 终态、评审要求、产物版本映射或经济计量规则，也没有数据迁移。

## 验证与限制

新增 18 个行为场景，强化既有 OpenClaw 停止回执测试。实际服务、隔离数据库和两种适配器
共同参与；仅外部传输使用替身，覆盖遥测异常、停止失败、宿主取消、收尾期间再次取消、
缺失产物、旧缓存、原会话引用及本地资源等待。

首轮观察到 17 个失败、1 个通过；其中 OpenClaw 直接清理用例的假地址连接等待掩盖了未等待
生产协程的问题。补齐即时传输替身，并优先断言停止目标后，8 个适配器场景均按预期失败。
强化的受控回执场景另外复现了 1 个失败，随后才修改生产代码。

修复后，初次定向检查 64 项通过；任务生命周期、交接验收、遥测、受控会话和 mock 等回归
共 **292 项通过**。静态检查纠正一处异常链声明后，最终管理运行器与清理 **71 项通过**，
5 个 Python 文件 Ruff 和格式检查通过。[原始验证记录](evidence/m3-u15-producer-cleanup.json)。
没有付费模型调用、Docker 操作、开发数据库写入或共享夹具改动，用户 `tmp/` 未读取或修改。

接下来需保存停止意图并核对原运行终态，将取消、预算停止和技术恢复接入同一持久执行事实。
技术重试耗尽转 blocked、管理解除阻塞、进程恢复及真实“停止／未确认停止”证据仍须分别验收。
