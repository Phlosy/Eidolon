## 对用户可见的结果

Manager 能读取能力缺口、内部员工、市场人才与真实价格，再通过七类动作处理缺口。
系统校验身份、权限、预算与领域条件，保存决定及逐项执行结果；它不会自行选择动作或人才。

| 动作 | 真实入口 |
| --- | --- |
| 学习 | `create_learning_priority` / `request_training` |
| 选择内部员工 | `assign_task` |
| 改派已有任务 | `assign_task` / `update_task` |
| 招聘 | `recruit_from_market` |
| 改方案 | `update_task` / `replan_project` |
| 拆任务 | `create_task` + `create_dependency` |
| 委派 | `delegate_project` |

学习动作只创建 Person 的学习意图，实际成长仍来自既有 Evidence 流程。招聘沿用原 Person
和 M1/T2 交易，不复制人才资产。招聘与支出双授权通过后，Owner 批准固定条款；执行时
再次检查身份、权限、期限与条款。成交只创建开通意图，环境真正就绪后才允许开工。

组合动作保留真实的 `PARTIALLY_APPLIED`。例如先建子任务成功、再连边因环被拒绝，
系统只记录前一步的效果；进程恢复和请求重放复用已保存的 ToolAudit，不重复建任务或扣费。
