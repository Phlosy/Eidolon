## 协议与边界

`RuntimeReply` 保存宿主会话 ID、请求 ID、外部运行 ID 和完整文本。
会话与请求共同生成远端幂等键，同一会话的轮次串行执行；普通事件队列不参与命令提取。
进程内已完成的请求保存回复与提示词摘要，同 key 重试直接返回原回复，不再次访问远端；
同 key 不同参数拒绝。每个会话最多保存 32 个不同请求，达到上限后拒绝新请求，保留已有回执。
这层缓存不代替后续业务桥的持久操作回执，也不宣称支持跨进程恢复。
一轮完成后仍可继续会话，不推进业务任务。Mock 和占位适配器明确不支持该通道。
连接、锁等待和响应读取受总超时约束；超时后的停止请求另有短时限。
停止请求不等于远端已确认停止，也不等于业务取消完成。
取消意图在远端请求前记录；回复只有在传输清理结束后、会话仍可执行时才能交还调用方。
OpenClaw 受控连接尚未取得运行 ID 时取消，不会转而停止普通共享会话。

## 真实调用及预算证据

验证先提交一个包含随机标记的 JSON 回复要求，再发送回执，要求模型从会话历史恢复该标记，
同时引用新回执的事实。两种运行时都返回了正确的第二轮 JSON，且两轮 run ID 不同、会话 ID 相同。
这证明真实传输、完整输出及上下文续轮；本次未以 Python 直接调用工具冒充业务桥验收。

测试使用隔离 SQLite、目录、网络和临时容器。每种运行时最多两次上游调用、每次最多 128 个输出
token、累计费用上限 0.05 美元。代理持久预留保守费用上界，已知可信用量才结算；失败、缺失用量
或无法确认的响应保留预留费用。并发请求、重启和损坏账本均不能重置预算。
原 U4 的默认值仍为一次调用、32 个输出 token。

首次 Hermes 验证发现自动会话标题占用了一次额外模型调用，第二个业务轮次被代理拒绝。
固定镜像源码确认 `auxiliary.title_generation.enabled=false` 可关闭该功能；宿主管理的 Hermes
配置现在显式关闭它，修正后仅重跑 Hermes，两轮通过。已有运行容器没有被改写或重启。
