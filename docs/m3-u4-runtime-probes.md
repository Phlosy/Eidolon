## 就绪事实

容器存在、进程健康、应用健康、鉴权控制通道、必需能力分别保存为事实；Provider
配置、连通性和选定模型调用也分别判断。每项都有 `state`、`reason`、
`checked_at`、`expires_at`，缺失、过期或不合法的记录返回 `unknown`。

控制与连通性事实有效期为 90 秒，明确执行的模型验证回执有效期为一小时。
Runtime 的容器、连接、控制凭证或已应用配置变化后，旧控制事实失效；Provider、
模型、端点或凭证引用变化后，旧模型事实失效。配置渲染时记录已应用指纹，健康复用
不把尚未应用的新配置冒充为已生效。

真实 Runtime 仅在运行状态且全部必需事实通过时满足相应就绪项。模型列表可读
不能证明选定模型可调用。mock 的既有必答项、四项就绪词表和任职软契约保持不变。
兼容增补先登记于 [M2 冻结文档](m2-freeze.md)。

## 宿主机控制通道

本机 conda 后端无法解析 Docker 私有网络里的容器名称。新增 `loopback` 模式，
创建前持久预留 26900–26921、26923–26989 中的端口，并仅绑定 `127.0.0.1`。
分配跳过已登记端口、宿主监听和 Gitea 保留端口；数据库唯一索引处理并发争用。
compose 后端显式使用 `docker` 模式，保持容器私有网络连接。

已有容器保留原连接方式，不由对账自动重建。需要应用新方式时走明确重建动作。
端口与网络规则见 [端口登记](ports.md)、[Docker 说明](runtime/docker.md)。

Hermes 通过公开健康端点与鉴权 capabilities 端点分别验证应用和控制通道，检查
run submission、status、SSE events、stop 能力；错误令牌必须被拒绝。

OpenClaw 固定镜像使用 protocol 4。宿主控制器保存独立的加密 Ed25519 身份，
按挑战 nonce 签名，并校验实际授予的 read/write scopes。首次配对仅可在归属标签
匹配的容器中批准该控制器的精确请求 ID；设备、角色、scope 或客户端不匹配即拒绝。
验证的是再次从宿主建立的控制连接，不能只凭本地 CLI 的批准回执判定通过。

自定义 OpenClaw Provider 补齐固定镜像要求的模型目录及环境凭证引用。两种 Runtime
都保留用户明确配置的 Provider 端点，避免就绪指纹与实际渲染配置不一致。

## 免费刷新与显式模型验证

- `GET /api/v1/runtimes` 和单实例 GET：只读已保存的事实；响应仅包含白名单字段。
- `POST /api/v1/runtimes/{id}/probe`：刷新低成本控制/连通性事实，可以配对本实例
  已登记的宿主控制器，不启动模型运行。
- `POST /api/v1/runtimes/{id}/validate-model`：显式发起一次选定模型验证。

模型验证请求必须包括 `allow_paid: true`、`idempotency_key`、`max_cost_usd`。
仅允许一个请求，时限最多 30 秒，输出最多 128 token，预算最多 1 美元；固定使用
极短提示词，没有工具、历史、自动重试或备用模型。读面、派发和后台对账不会调用它。

调用前还须在该 Provider 的 `metadata.probe_pricing.<model>` 提供价格：
`input_usd_per_million`、`output_usd_per_million`、`valid_until` 和 `source`。
价格必须仍有效，且有效截止时间不超过未来七天。缺少价格或保守估算超预算时，
请求在联网前被拒绝。可通过现有 Provider PATCH 的 `metadata` 字段维护。

数据库在联网前提交调用意图和预算。key 同时绑定实例资源标识和创建时间，避免数据库
编号复用后错误继承旧回执。同一 key/同一配置/同一参数再次请求会读取回执；
参数冲突或另一个正在运行的验证返回冲突，不会多发模型请求。进程中断留下的请求
超时后仍以未知回执返回，不能自动补发。当前公司和 Provider 可见性在独立数据库
阶段重新校验。并发回写使用条件更新，不能覆盖已结束尝试或更新后的实例元数据。

回执保留请求次数、价格依据、用量和按价格计算的费用，不保存模型正文或隐藏思考。
无用量、超时或传输不确定时费用保持未知。这里的费用由声明价格估算，厂商最终账单
及超额行为仍以实际回执为准；已观察到超出 token/费用边界的响应不会通过验证。

## 异步对账

启动仅创建后台任务，不等待远程探测完成。每轮以有限并发观察实例，数据库阶段与
Docker/HTTP 调用分离；周期检查复用尚未过期的 Provider 连通性记录，手动刷新可
强制重测。Docker 不可达返回未知，与已确认容器缺失区分。

行无容器、容器停止、健康未知、控制鉴权失败和能力缺失都有明确原因。写回时校验
实例版本及开通领取状态，旧探测不能覆盖并发重建或停止。孤儿仅发布
`runtime.orphan_detected`，不会删除；已有稳定资源 key/name 的创建中容器受到保护。
孤儿重复事件按当前容器 ID 去重，关联员工批量读取，避免扫描全部历史事件。
